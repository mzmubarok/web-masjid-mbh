# UI Guidelines

**Version:** 1.0  
**Status:** Planning

---

# Overview

This document defines the visual design guidelines for the Masjid Baitul Hikmah website and Content Management System (CMS).

The goal is to maintain a consistent, accessible, and professional user interface across all pages and modules.

These guidelines should be followed whenever new UI components or pages are created.

---

# Design Principles

The UI should prioritize:

- Simplicity
- Consistency
- Readability
- Accessibility
- Responsiveness
- Performance

Avoid unnecessary visual complexity.

---

# Design System

The application should use a unified design system.

All components should follow the same:

- Colors
- Typography
- Spacing
- Border Radius
- Shadows
- Icons
- Buttons
- Forms

---

# Typography

Typography should establish a clear visual hierarchy.

Recommended hierarchy:

- Page Title
- Section Title
- Card Title
- Body Text
- Caption
- Helper Text

Guidelines:

- Use consistent font weights.
- Avoid excessive font sizes.
- Maintain comfortable line height.
- Ensure readability on all devices.

---

# Color Palette

The project uses a predefined color palette.

Colors should have clear semantic meaning.

Examples:

Primary

- Brand color

Secondary

- Supporting color

Success

- Positive actions

Warning

- Caution

Danger

- Destructive actions

Neutral

- Backgrounds
- Borders
- Text

Avoid introducing new colors without updating the design system.

---

# Spacing

Use a consistent spacing scale throughout the application.

Spacing should be predictable and reusable.

Apply consistent spacing between:

- Sections
- Cards
- Form fields
- Buttons
- Tables

---

# Border Radius

Use consistent corner radius values.

Apply the same style to:

- Cards
- Buttons
- Inputs
- Dialogs
- Images

Avoid mixing multiple radius styles.

---

# Shadows

Use shadows sparingly.

Purpose:

- Visual separation
- Elevation
- Focus

Avoid excessive shadow effects.

---

# Icons

Icons should:

- Be consistent in style.
- Match surrounding text size.
- Support the content.
- Never replace meaningful labels.

---

# Buttons

Buttons should have clear hierarchy.

Primary

Main action.

Secondary

Alternative action.

Outline

Less prominent action.

Destructive

Delete or irreversible actions.

Disabled

Unavailable actions.

Loading

Processing state.

---

# Forms

Forms should maintain consistency.

Each form should include:

- Label
- Input
- Helper Text (optional)
- Validation Message
- Required Indicator (when applicable)

Related fields should be grouped together.

---

# Tables

Tables should support:

- Search
- Sorting
- Pagination
- Empty State
- Loading State

Rows should remain readable on all screen sizes.

---

# Cards

Cards should use a consistent structure.

Typical card layout:

- Header
- Content
- Footer (optional)

Cards should maintain consistent padding and spacing.

---

# Dialogs

Dialogs should be used for:

- Confirmation
- Editing
- Creating
- Important notifications

Destructive actions should always require confirmation.

---

# Navigation

Navigation should remain consistent across the application.

The active page should always be clearly indicated.

Avoid deeply nested navigation.

---

# Loading States

Every page should display an appropriate loading state.

Examples:

- Skeleton Loader
- Loading Spinner
- Disabled Button

Avoid layout shifts while loading.

---

# Empty States

Empty states should guide users.

Examples:

"No events available."

"No gallery photos found."

"No financial reports yet."

Whenever possible, provide a related action.

---

# Error States

Errors should be presented clearly.

Avoid technical language.

Whenever possible:

- Explain the issue.
- Suggest a solution.
- Provide a retry action.

---

# Notifications

Use toast notifications for:

- Success
- Warning
- Error
- Information

Notifications should be brief and meaningful.

---

# Accessibility

The interface should follow accessibility best practices.

Requirements:

- Sufficient color contrast.
- Keyboard navigation.
- Visible focus indicators.
- Screen reader friendly labels.
- Accessible form controls.

---

# Responsive Design

The application should support:

Desktop

Tablet

Mobile

Layouts should adapt gracefully without losing functionality.

---

# Images

Images should:

- Be optimized.
- Maintain aspect ratio.
- Include alternative text.
- Use lazy loading where appropriate.

---

# Consistency

Every page should feel like part of the same application.

Developers should reuse existing components whenever possible.

Avoid creating duplicate UI patterns.

---

# Future Improvements

Potential future enhancements include:

- Dark Mode
- Theme Customization
- Multi-language Typography
- Animation Guidelines
- Illustration Guidelines
